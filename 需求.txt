# 智能 Agentic RAG 框架 - 完整需求规范

## 1. 核心目标
构建一个智能 Agentic RAG 框架，用于：
- 处理 PDF 格式电子书（大部分扫描版，需 OCR；少部分可直接提取文字）
- 自动合并跨页段落
- 使用 OpenAI 风格 API 接入模型
- 摘要索引 + 内容链接机制
- 支持多步迭代推理直到形成答案

## 2. 数据处理流程

### 2.1 PDF 解析与 OCR（增强版）
**扫描版 PDF：**
- **多OCR引擎支持**：PaddleOCR（中文优化）、Tesseract（多语言支持）、EasyOCR（备选）
- **OCR质量评估**：引入置信度评分机制，低置信度文本标记为待人工审核
- **图像预处理**：自动进行图像增强、去噪、二值化处理提升OCR准确率
- **多模态备用方案**：当传统OCR失败时，使用 GPT-4V、Qwen-VL 作为备用方案

**可直接提取文字的 PDF：**
- 主引擎：PyMuPDF（性能优先）
- 备用引擎：pdfplumber（表格处理优化）
- 编码处理：自动检测和处理特殊字符编码

**图像/表格提取增强：**
- 从 PDF 页面中提取图像，支持多种格式（PNG, JPEG, WebP）
- 识别并提取表格结构，结合规则匹配和深度学习模型
- 质量检查：提取后内容完整性验证

### 2.2 段落合并机制（算法细化）
**跨页段落检测：**
- 分析页面间文本的连续性（字体、大小、行距、位置）
- 检测段落是否被页面分割

```python
# 连续性检测权重分配
CONTINUITY_FACTORS = {
    "font_similarity": 0.3,      # 字体相似度
    "line_spacing": 0.2,         # 行距一致性  
    "text_alignment": 0.2,       # 文本对齐方式
    "semantic_continuity": 0.3   # 语义连续性（使用轻量模型）
}

# 合并置信度阈值
MERGE_CONFIDENCE_THRESHOLD = 0.7  # 低于此值需要人工审核
```

**自动合并策略：**
- 高置信度（>0.85）：自动合并跨页段落
- 中等置信度（0.7-0.85）：提供合并建议
- 低置信度（<0.7）：标记待人工处理
- 保留原始页面信息作为元数据

### 2.3 内容截取与存储（增强版）
**文本截取优化：**
- 动态分块策略：根据语义边界而非固定长度分块
- 智能重叠控制：避免信息丢失的重叠机制
- 内容去重：基于内容哈希的重复内容检测

**图像截取：**
- 从 PDF 页面中提取的图像
- 保存为独立文件，生成内容链接
- 支持压缩和格式转换优化

**表格截取：**
- 提取的表格数据
- 转换为结构化格式（JSON/CSV）保存，生成内容链接
- 同时保存可视化格式用于显示

### 2.4 摘要生成（成本优化）
**文本摘要：**
- 调用 OpenAI 风格 API（如 GPT、Qwen）生成文本摘要
- 分层摘要策略：关键内容详细摘要，次要内容简洁摘要
- 缓存机制：相同内容避免重复生成摘要
- 附带原文内容链接

**多模态摘要：**
- 调用多模态 API（如 GPT-4V、Qwen-VL）生成图像/表格描述
- 本地模型优先：降低API调用成本
- 批量处理优化：多个内容批量生成描述
- 附带对应内容链接

## 3. 知识库存储设计增强

### 3.1 内容存储系统（健壮性提升）
**文本内容：**完整段落存储在数据库（PostgreSQL/MongoDB）
**图像内容：**图像文件存储在文件系统（支持本地和云存储）
**表格内容：**结构化数据存储 + 可视化格式
**内容链接：**唯一标识符用于快速查找，支持永久链接

**存储优化：**
- 元数据管理：丰富的处理历史和质量记录
- 版本控制：内容更新时的版本管理
- 备份机制：定期备份和恢复测试

### 3.2 向量化索引（Milvus性能优化）
**索引内容：**摘要向量 + 内容链接
**元数据：**包含指向完整内容的链接

**Milvus配置优化：**
- 集合分区：按内容类型分区提高查询效率
- 索引选择：根据查询模式选择合适索引类型
- 资源管理：连接池和批量插入优化

## 4. 查询与迭代推理流程（可靠性提升）

### 4.1 初始查询处理
- 用户提问 → 向量化 → Milvus 检索相似摘要
- 返回：相关摘要 + 内容链接
- 查询预处理：拼写检查、查询扩展、意图识别

### 4.2 内容获取（容错机制）
- 通过内容链接获取完整原文/图像/表格
- 准备：摘要 + 完整内容
- 重试机制：获取失败时的自动重试
- 降级策略：主要内容不可用时的备用方案

### 4.3 多模态推理（成本控制）
- 将摘要和完整内容送入多模态模型
- 判断推理结果：
  - 如果能直接回答 → 返回最终答案
  - 如果只能生成中间问题 → 进入下一步
- 模型选择策略：根据内容复杂度选择合适模型

### 4.4 迭代推理机制（智能终止）
**中间问题生成：**
- 模型识别需要进一步信息才能回答
- 生成具体的子问题
- 子问题质量检查：相关性、可回答性、避免循环

**新查询检索：**
- 基于中间问题重新检索
- 获取新的相关摘要和内容

**重复过程：**
- 继续推理 → 生成新问题 → 重新检索
- 直到能够形成完整答案

### 4.5 迭代终止条件（量化标准）
```python
TERMINATION_CONDITIONS = {
    "answer_completeness": 0.8,    # 答案完整性评分
    "confidence_threshold": 0.7,   # 置信度阈值
    "max_iterations": 5,           # 最大迭代次数
    "information_gain": 0.1,       # 信息增益阈值
    "query_specificity": 0.6       # 问题特异性
}
```

- 模型判断已获得足够信息
- 无法生成更有意义的子问题
- 达到最大迭代次数（防止无限循环）

## 5. OpenAI API 集成增强

### 5.1 API 调用配置
- 文本处理：调用 chat/completions 接口
- 多模态处理：调用 vision 接口（如 gpt-4-vision）
- 向量化：调用 embeddings 接口

### 5.2 API 参数化优化
- 模型名称、温度、最大长度等参数可配置
- 支持不同服务商的 OpenAI 兼容接口
- API密钥管理：安全存储和轮换机制

## 6. 架构组件（增强版）

[PDF输入] → [OCR解析器] → [段落合并器] → [内容截取器] → [内容存储]
↓
[OpenAI API摘要器] → [摘要+链接生成] → [Milvus索引]
↓
[查询处理器] → [摘要检索] → [内容获取] → [多步迭代推理] → [最终答案]

**系统增强特性：**
- 插件架构：支持OCR引擎、模型接口等的插件式扩展
- 配置驱动：所有参数通过配置文件管理
- 并行处理：支持多文件并行处理
- 监控告警：健康检查、性能监控、资源告警

## 7. 迭代推理流程示例

用户问题: "这本书中关于机器学习的章节是如何介绍神经网络的？"

Step 1: 检索 → 从混合知识库中找到最相关的"机器学习神经网络"内容块
Step 2: 推理 → "找到了多个相关内容块，需要综合这些信息"
Step 3: 子问题 → "神经网络的不同实现方法有哪些？"
Step 4: 重新检索 → 找到更多关于神经网络实现的相关内容
Step 5: 推理 → "综合所有相关信息，可以完整回答问题"
Step 6: 最终答案 → 生成综合多来源的神经网络详细介绍，并注明参考书籍
